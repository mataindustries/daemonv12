# DAEMONV12 · SAMPLE LAB 01 / EXPERIMENT 01

Two original, sample-driven four-bar loops at 96 BPM. Both are built from the same small palette of recordings and
cut from the same self-made source record.

**Status: waiting for human listening approval.** Nothing here has been released. No engine, Composer or site code was
changed: everything lives in this folder, and every render uses DaemonV12 0.7.0 as it is on `main`.

## How it is built

```text
palette (8)  keys-take, bass-db [new] · ghost-vox, glass-hit, pixel-hat [GLASSHOUSE CC0] · air-texture, mechanical-kick, industrial-snare [Orbital Foundry CC0]
   │
   ├─▶ crate-01.json ──render──▶ crate-01.wav   (the shared "record": keys + two-voice ghost-vox group + glass + air)
   │                                │
   │                                ├─▶ dusty-pocket.json   chops (oh/ah regions) + bass + kick/snare/hat + air shaker
   │                                └─▶ cosmic-collage.json bed + drone (same chop, sinking) + bass + drums + knock + air + ghost
   └─▶ glass-choir.json ──render──▶ glass-choir.wav (voice + octave-down voice + glass) ──▶ cosmic-collage hook
```

| Path | What |
|---|---|
| `scripts/generate-sources.ts` | The two new recordings (Node built-ins, seeded, no inputs) |
| `scripts/crate-01.ts` | The source record and its exact chop regions |
| `scripts/dusty-pocket.ts`, `scripts/cosmic-collage.ts` | The scores: every event, offset, gate, rate and mix decision, with comments |
| `scripts/score.ts` | Tick and pitch helpers (960 PPQ; one tick is 0.651 ms at 96 BPM) |
| `scripts/build.ts` | The whole pipeline below |
| `projects/*.json` | The arranged DaemonV12 projects, generated by the scores; open or render them directly |
| `projects/assets/` | The palette and the two resampled prints, as the projects reference them |
| `deliverables/<candidate>/` | Loop WAV and MP3, `stems/` (aligned, 441,000 frames each), `.events.json` (DaemonV12 event map), `.groove.svg`, engine `.render.json` |
| `deliverables/CHECKS.md`, `checks.json` | Format, loudness, clipping, seam, stem-alignment, MP3 and timing checks |

**Event maps** use the repository's own `daemonv12-event-map` format (`src/sync`). `clipSampleFrame` is the frame inside
the delivered loop. Each event's `source` records its musical position, its authored grid position, its human offset in
ms and ticks, its velocity, rate, slice, gate, choke group and, for chops, the CRATE-01 region it reads.

**Stems** include each track's gain, pan, effects and automation, and exclude the master chain (gain, 28 Hz high-pass,
compressor, saturation), as the engine defines them. They are cut from the same render window as the master; their sum
correlates best with the master at lag 0.

## Rebuild

From the repository root, with Node 22.18+ and FFmpeg:

```sh
node experiments/sample-lab-01/scripts/build.ts
```

It takes about 90 seconds. It regenerates the sources twice (failing if they differ), rewrites every project, renders
both prints and both candidates (two cycles plus a bar of tail room, and a three-cycle seam proof), and rewrites
`deliverables/` and `sources.manifest.json`. Running it twice in a row in this environment (Linux, Node v22.22.0,
FFmpeg 6.1.1-3ubuntu5) left `git status` clean: every WAV, MP3, stem, map and report was byte-identical.
Intermediate renders go to `work/`, which git ignores.

## Out of scope

No video, no animation, no DaemonV12 rebuild and no DSP-engine work. Every limit the engine has (no reverse playback,
no sidechain, filters without automation) was handled in the arrangement: envelopes for swells, authored gain
automation for ducking, a parallel filtered bed. None of them was patched in the engine.
