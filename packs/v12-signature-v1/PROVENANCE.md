## How the audio came to exist

| Evidence | Detail |
|---|---|
| Generator | `scripts/generate-v12-signature.ts`, a single TypeScript file. Imports only `node:fs` (`mkdirSync`, `writeFileSync`; it reads no files), `node:path`, `node:url` and `node:crypto`. |
| Inputs | Numeric parameters in that file and seeded xorshift32 noise (seeds in the catalog). No recordings, downloaded samples, loops, SoundFonts, impulse responses, presets, analysis of existing songs or embedded audio data. |
| Method | Additive, subtractive, FM, modal and formant synthesis; filters, waveshaping and diffusion written in the file. Every recipe is summarised in each catalog entry's `method` field. |
| Inspiration | Generic synthesis families (tuned kicks, supersaw leads, open-fifth pads, formant vowels, bell modes). No artist, record, preset or copyrighted recording was imitated or referenced. The CHROME modes are an equal-tempered minor-third bell model; the vowel formants are textbook-style values chosen by hand. |
| Projects | `scripts/create-v12-signature-projects.ts` writes the audition and showcase JSON. They reference only this pack's WAVs and kit; no General MIDI. The showcase hook, progression (Am–F–G–E) and arrangement were composed for this pack. |
| Renders | Made by the unchanged DaemonV12 0.7.0 engine (Node 22.22.0, FFmpeg 6.1.1-3ubuntu5 for the showcase's production route). |
| Reproducibility | Two fresh processes regenerate all 20 files (16 WAVs, kit, catalog, two projects) byte for byte; `npm run verify:v12-signature` re-checks this and records SHA-256 values and the generator's own hash in `v12-signature.verification.json`. |
| Authorship | Generated by an AI agent (Claude) working in this repository at the owner's request, on branch `feat/v12-signature-pack-v1`. The owner should record whether they treat this as commissioned work. |

## Owner decision checklist

1. Decide the license for the sixteen WAVs and the two rendered demos (for example
   CC0-1.0 like Orbital Foundry and GLASSHOUSE, or a custom grant).
2. Record it in `PROVENANCE.md`, a `LICENSE` file in `assets/v12-signature/`, and
   the catalog `license` field (change `catalog()` in the generator and regenerate).
3. Only then consider promoting the pack into `examples/assets/` (which `init`
   copies into every workspace and the npm package ships).
4. If the pack is used in a commercial benchmark or licensing deal, follow the
