# BANGER LAB 001 · Launch specification

**Goal:** one genuinely memorable, original 75-second dark, futuristic,
hypnotic electronic instrumental with commercial potential, made with DaemonV12
and chosen by human ears. Music first: measurements serve listening and never
replace it.

**Status:** prepared, not started. No contestant has run, nothing has been
composed, rendered for release or deployed. This folder is documentation,
specifications, prompts, a palette file, templates, one read-only check script
and one organizer probe. Nothing in the engine, the Composer plugin, Round 2/3
materials, the site, existing benchmarks or the sound assets was changed.

## 1. Final recommended challenge design

A **producer room** with a built-in controlled test, run in six stages
(`RULES.md` §2):

1. **Sonnet 5.5 (prompt A)** composes the complete 75 s record under Composer
   v0.3 Benchmark Mode: meaningful V1 → V2 → V3 (three named weaknesses before
   each revision, musical changes only), the full review and Risk Pass, optional
   justified V4/V5, then a deterministic lock with cues and a 15 s promo window.
2. **Haiku 5.5 (prompt B)**, in parallel and isolated, makes three 15 s
   hook-and-groove sketches in three distinct directions, each with V1 → V2.
3. **Humans (prompt C)** judge blind, loudness-matched copies: S1, the hook pool
   (sketches + the lead's promo excerpt, identical 10 ms edges); S2, the version
   pool (V1/V2/V3); and a 24-hour recall test for memorability.
4. **Opus (prompt D)**, after the reveal, writes a producer's revision brief:
   protected elements and at most five changes, each a filled Astra task card,
   or "lock as is".
5. **Astra (prompt E)** runs one narrow task per session (end repair, kick/bass
   spacing, gain staging, hook transplant, enumerated section edit, promo edit,
   delivery packaging). Each task has byte-level acceptance: unchanged audio is
   proven unchanged with `cmp`.
6. **Humans confirm** the final against the selected lead in a blind A/B. It
   ships only if it is preferred and nothing got worse.

**Optional controlled arm:** prompt B, unchanged, run by a fresh Sonnet session.
The six sketches give a fair same-task model comparison, reported only as
"under these conditions". The V1/V2/V3 version test is always run and tests
the Composer revision loop itself. Producer-room results never rank models.

Why this design: the best hook can come from anywhere, so the cheap model
explores and the strong model builds. Humans choose with matched loudness,
Opus directs from human evidence, and Astra changes only what was asked, with
proof. Each step preserves the original masters and records who contributed
what.

Technical reproducibility and commercial clearance are separate findings. Both
hold for the approved packs. The remaining pre-launch item is the owner's
one-line CC0 attestation (prompt C §0). The composition's own copyright status,
for AI-generated work with human selection, is an open legal question for
exclusive licensing (`AUDIT.md` §2.3).

## 4. Human judging process

Three or more listeners (ideally five or more, including a producer or music
supervisor and target-audience listeners). Matched-loudness blind copies,
randomized per listener. Volume is set once. A cold pass, then a free-replay pass
with the weighted rubric (Memorability 20, Identity 15, Groove 15, Bass and
percussion 10, Arrangement and payoff 10, Emotional or physical 10, Replay 10,
Production 10). A phone-speaker check, scores hashed before the reveal, and a
24-hour recall test. Decision rules and reporting with n and no significance
claims: `RULES.md` §7–8, prompt C.

## 5. Deliverable validation checklist

`RULES.md` §13, summarized:

- [ ] Seal recorded; `submission.json` complete; engine and Composer hashes verified
- [ ] `validate` OK; `tools/check-delivery.sh` exit 0: 3,307,500 frames (sketches 661,500), aligned stems, hashes match the manifest, zero clipping at every stage, zero full-scale samples, true peak ≤ −1.0 dBTP, approved palette only, no GM, final 10 ms ≤ −50 dBFS
- [ ] A second fresh render is byte-identical (WAV, MIDI, stems, analysis, manifest)
- [ ] The final master equals the chosen version's master
- [ ] All delivery files present: editable project + assets, WAV, MP3, stems, `.render.json`, `.analysis.json`, production and revision log, `cues.json` with promo15
- [ ] V1–V3 diffs show musical changes matching the log's named weaknesses
- [ ] Cues re-resolve to identical frames; promo15 = 661,500 frames inside the container
- [ ] Blind copies verified (±0.3 LU of the pool target, ≤ −1.0 dBTP); key sealed
- [ ] Release: rights packet, resemblance review, owner attestation, `F-release/` sealed

## 6. Actual blockers

**None that prevent launch.** Preconditions to clear, in order:

1. **Owner CC0 attestation** for the two packs (one line, prompt C §0).
2. **Reference environment** for every session: FFmpeg 6.1.1 is required (the
   production route and analysis need it); FluidSynth is not. Run the preflight
   fingerprint; if the hashes differ, that environment becomes the only valid one.
3. **Model availability and settings** recorded for Sonnet 5.5, Haiku 5.5,
   Opus 5.5 and Astra (Astra's identity and tooling are organizer-supplied; its
   prompt is self-contained).
4. **Solo organizer blindness:** if the organizer also judges, someone or
   something else must make the blind copies (see the Codex task below, or an
   agent session following `RULES.md` §6).

Known non-blocking limits are in `AUDIT.md` §1.4: a small palette with no
sustained melodic source, no limiter, no master automation, and a hard container
edge.

## 7. Smallest next implementation task for Codex

**`benchmarks/banger-lab-001/tools/make-listening-copies.mjs`** (optional, and
worth doing if the organizer will also judge). It is a dependency-free Node
script that automates `RULES.md` §6 without revealing the mapping:

- Input: a pool JSON (`[{source, startFrame?, frames}]`, pool name, edge flag)
  and an output folder. The engine path comes from an argument.
- Steps: edge-treated excerpts for the hook pool; measure with
  `node bin/daemonv12.js analyze`; compute `T = floor10(min(-16, min(L - TP - 1)))`;
  apply static gain with the verified FFmpeg flags; re-measure; assign
  4-character IDs and per-listener orders from a seeded PRNG (the seed is a
  required argument and is recorded only in the key); write
  `private/blind-key.json`. Stdout shows only T, the IDs, the per-listener orders
  and the key's SHA-256.
- Acceptance: on a pool of the preflight probe and the GLASSHOUSE audition
  excerpt, every copy is within ±0.3 LU of T with true peak ≤ −1.0 dBTP and exact
  frames; a second run with the same seed is byte-identical; the inputs are
  unchanged (hashes); stdout contains no source path. Also add two negative
  fixtures to `check-delivery.sh` coverage: a manifest with a non-palette asset
  and one with `clippedSamples` > 0 must both exit 1.
- Out of scope: any engine, Composer or asset change.
